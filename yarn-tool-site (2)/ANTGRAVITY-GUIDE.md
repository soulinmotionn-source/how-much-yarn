# ANTGRAVITY-GUIDE.md — Agent Instructions for the YarnYardage Site

> **Read this file before making any change to this project.**
> It tells you how this site is built, what you may edit, and how to verify your work.

## 1. What this project is

A static, SEO-focused tool website: an interactive **yarn yardage calculator**
plus programmatic long-tail project pages (`projects/`) and supporting guide
articles (`guides/`). Zero backend, zero frameworks. Deploys to Cloudflare Pages.

## 2. Golden rule

**Never edit generated HTML by hand.** All HTML pages, `sitemap.xml`, and
`robots.txt` are generated by `build.py` from data files. Your workflow is always:

```
edit data (JSON / JS / CSS) → run `python3 build.py` → verify → commit
```

If you edit a `.html` file directly, your change will be wiped on the next build.

## 3. File map

| File | Edit? | Purpose |
|---|---|---|
| `projects.json` | YES | Data for the 18 long-tail calculator pages (slugs, keywords, intros, FAQs) |
| `guides.json` | YES | Data for the 8 guide articles (sections, internal links, FAQs) |
| `calculator.js` | YES | `PROJECT_YARDAGE` data table + calculator widget logic |
| `styles.css` | YES | All styling (mobile-first) |
| `build.py` | YES (careful) | The generator. Config block at top: `SITE_URL`, `SITE_NAME`, `CONTACT_EMAIL` |
| `index.html`, `projects/*.html`, `guides/*.html` | NO | Generated output — do not touch |
| `sitemap.xml`, `robots.txt` | NO | Generated output — do not touch |
| `ANTGRAVITY-GUIDE.md`, `UPDATE-GUIDE.md`, `DOMAIN-IDEAS.md`, `yarn-keywords-seo.xlsx` | YES | Docs / research, not deployed as site content |

## 4. Build and preview

```bash
cd <repo-root>
python3 build.py            # regenerates all pages; FAILS LOUDLY on SEO violations — fix them
python3 -m http.server 8000  # preview at http://localhost:8000
```

`build.py` automatically validates: title length (50–60 chars), meta description
length (150–160 chars), single H1 per page, valid JSON-LD, and unbroken internal
links. If the build passes, the SEO basics are intact.

## 5. Common tasks

### Add a new long-tail project page (e.g. a flagged expansion keyword)
1. Add yardage numbers to `PROJECT_YARDAGE` in `calculator.js`:
   `"dog-sweater": { sport: 400, dk: 350, worsted: 300 }`, plus a label in `PROJECT_LABELS`.
2. Append an entry to `projects.json` (copy an existing entry's shape exactly):
   unique `slug`, `key` (must match the `calculator.js` key), target `keyword`,
   `h1`, 2-paragraph `intro` (paragraph 1 = the direct "quick answer"),
   3–6 `secondary` search phrases, 4 `faqs`, `title` (50–60 chars), `meta_desc` (150–160 chars).
3. Run `python3 build.py`. Nav links, related-project links, sitemap, and
   JSON-LD are generated automatically.

### Add a new guide article
1. Append an entry to `guides.json` following the existing shape: 400–700 words
   of genuinely useful content, 3–4 FAQs, 2–4 contextual internal links to
   project pages (`../projects/<slug>.html`) and other guides (`<slug>.html`).
2. Run `python3 build.py`.

### Change domain / go live
1. In `build.py`: set `SITE_URL` (no trailing slash) and `CONTACT_EMAIL`.
2. Run `python3 build.py` — canonicals, sitemap, and JSON-LD URLs update.

### Styling changes
Edit `styles.css` only. Keep the mobile/accessibility rules intact (see §6).

### Turn on real AdSense units
Each page has 3 commented placeholders (`<!-- AdSense: … -->` + `<div class="ad-slot">`).
Replace the placeholder div with the responsive ad unit snippet. Keep the reserved
`min-height` so layout doesn't shift (CLS). Do not add more than 3 ad units per page.

## 6. Guardrails — do not break these

- Titles 50–60 chars, meta descriptions 150–160 chars (build enforces).
- One H1 per page; logical H2/H3 order; semantic tags (`header/main/nav/article/footer`).
- JSON-LD blocks must remain valid JSON (build validates).
- Internal links: relative paths, descriptive anchor text, no broken targets.
- Every new page must be reachable: link it from the homepage grid or guides index, and link back.
- Accessibility: 48px minimum tap targets on controls, 16px+ base font, visible
  `:focus-visible` outlines, `<label>` on every form control, `alt` text on images,
  honor `prefers-reduced-motion`. Tables must scroll horizontally on 360px screens.
- Performance: no frameworks, no render-blocking external resources, keep CSS/JS small.
- Ad policy: never add click-encouraging text near ads; keep the cookie banner,
  privacy policy (with ad-vendor disclosure), and footer disclosure intact.

## 7. GitHub + Cloudflare Pages workflow

1. Push this folder to a GitHub repo (repo root = site root). Commit the generated
   HTML too — it keeps deploys reproducible.
2. Cloudflare dashboard → Pages → Connect to Git → select the repo.
   - Framework preset: **None**
   - Build command: `python3 build.py`
   - Build output directory: `/` (leave as project root)
3. Every push to the main branch auto-rebuilds and redeploys. Preview deployments
   are created for pull requests — use them to review changes before merging.
4. After first deploy: submit `https://<domain>/sitemap.xml` in Google Search Console.

## 8. Verification checklist (run before every commit)

- [ ] `python3 build.py` completes with no SEO warnings
- [ ] New/changed pages load at `http://localhost:8000` and the calculator computes correctly
- [ ] New pages appear in `sitemap.xml`
- [ ] No new external render-blocking resources added
- [ ] Mobile: no horizontal overflow at 360px (tables scroll, tap targets ≥ 48px)
